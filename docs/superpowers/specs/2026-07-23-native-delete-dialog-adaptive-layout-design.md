# Native 删除确认框自适应布局设计

## 背景

Native 文件管理器的删除确认框当前固定为 `380×138`。短文件名只占据左上角，正文、路径和按钮之间产生大面积空白，缺少内容包裹感。

## 目标

- 根据文件名的实际渲染宽度动态调整窗口宽度。
- 短文件名使用紧凑窗口，正文与按钮之间不保留多余高度。
- 窗口宽度限制在约 `260–520px`。
- 超长文件名和路径在达到最大宽度后自动换行，并通过增加窗口高度完整显示。
- 保持居中、不可手动缩放、背景遮罩以及红色删除按钮。

## 布局方案

使用 egui 当前字体系统测量确认文案的单行渲染宽度，避免按字符数估算导致中英文、符号和 emoji 宽度失真。目标宽度为文案宽度加窗口内边距，并限制在最小和最大宽度之间。

删除窗口不再使用固定高度。窗口宽度由计算结果约束，正文和路径标签启用自动换行，egui 根据换行后的内容、间距和按钮行计算最终高度。按钮行紧跟正文底部。

路径不参与扩大窗口宽度，始终在由文件名决定的宽度内换行，防止深层路径导致弹窗横向占满屏幕。

## 测试与验证

- 单元测试验证短文件名使用最小宽度、较长文件名会增加宽度、超长文件名不会超过最大宽度。
- 运行 `native-prototype/build.sh`，确认格式、编译、Clippy 和全部测试通过。
- 启动 Native 客户端，分别对短文件名和超长文件名打开删除确认框，检查紧凑包裹、自动换行、动态高度和按钮位置。
