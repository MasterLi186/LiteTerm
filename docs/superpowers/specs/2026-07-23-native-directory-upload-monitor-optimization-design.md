# Native 目录上传与监控优化设计

## 目标与顺序

先让 Native 文件管理器支持从本地右键递归上传目录，再降低系统监控造成的内存、CPU 和文件描述符开销。保留现有单文件上传、远端文件下载、重命名和删除行为；远端目录下载不在本次范围内。

## 方案选择

目录上传可选择逐项发送 worker 命令、先打包再上传，或在现有 SFTP worker 中递归流式上传。采用第三种：它不创建临时压缩包，不阻塞 UI 线程，并复用现有连接和进度事件。

监控可限制缓存数量、调用外部 `ps`，或继续使用 `sysinfo` 但禁用任务扫描与文件缓存。采用第三种：改动最小，仍能提供当前 UI 所需的进程 CPU、内存和名称。

## 递归目录上传

本地目录右键菜单中的“上传到远程”在 SFTP 就绪时可用；远端目录的“下载到本地”仍禁用。上传目标为“当前远端目录/本地目录名”。

worker 在传输前构建确定性的本地上传清单：

- 根目录及子目录在远端按需创建，空目录也保留。
- 普通文件按现有 64 KiB 分块流式上传。
- 总进度以目录内所有普通文件的字节总和计算，沿用一个传输 ID。
- 目录遍历或任一文件上传失败时发送现有失败事件；已上传的部分不自动删除。
- 符号链接返回明确错误，不跟随链接，避免目录循环和越界上传。
- 遇到已存在的远端目录时继续；目标存在但不是目录时失败。

纯本地的清单生成、相对路径和总字节计算独立成可测试函数；SFTP I/O 保持在 worker 线程。

## 系统监控优化

当前 `refresh_processes` 默认包含所有任务，并让 Linux `sysinfo` 为每个进程/线程缓存 `/proc/.../stat` 描述符。监控 UI 只显示进程级名称、CPU 和内存，因此改为：

- 初始化 collector 前调用 `sysinfo::set_open_files_limit(0)`。
- 使用 `refresh_processes_specifics`，仅请求 CPU 和内存。
- 不启用 `tasks`，避免为数千线程创建记录。
- 保持两秒采样周期、磁盘、网络和 UI 排序不变。

## 测试与验收

- 单元测试覆盖嵌套目录、空目录、总字节、符号链接拒绝和菜单启用规则。
- 现有单文件上传与全部 Native 测试继续通过。
- 使用临时本地目录和测试远端路径进行真实递归上传，核对目录树和文件内容。
- 重启 Native 后比较 `/proc/<pid>/status`、`smaps_rollup` 和 FD 数量；目标是 `/proc/*/task/*/stat` FD 为零、总 FD 回落到正常数量，且监控数据仍刷新。
- 使用 `native-prototype/build.sh` 完成编译、Clippy 和测试门禁。
