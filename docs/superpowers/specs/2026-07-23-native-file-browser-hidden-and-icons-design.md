# Native 文件管理器隐藏文件与基础图标设计

## 目标

Native 文件管理器默认不显示名称以 `.` 开头的文件和目录，并以稳定、清晰的图标区分目录与普通文件。视觉密度、配色及交互继续忠于 main 的紧凑双栏文件管理器。

## 范围

本阶段只实现两类图标：

- 目录：黄色文件夹图标
- 普通文件：灰色文档图标

代码、文本、图片、压缩包等扩展名图标留到下一阶段。本阶段不增加“显示隐藏文件”开关，也不改变列表、上传、下载、刷新和路径导航行为。

## 数据与过滤

本地和远端目录读取结果保持完整，不在 SFTP 或本地文件系统层删除条目。UI 渲染列表时调用统一的可见性判断，过滤 `entry.name.starts_with('.')` 的条目。标题中的项目数量按实际可见条目计算，避免显示数量与列表内容不一致。

将过滤规则提取为可独立测试的小函数，后续增加“显示隐藏文件”开关时只需扩展显示条件，无须改动数据加载流程。

## 图标绘制

不再使用 Unicode 字符作为文件类型标记。当前黄色方块是字体缺少对应字形导致的，继续依赖字符无法保证不同 Linux 环境下的显示结果。

图标使用 egui `Painter` 绘制：

- 文件夹由文件夹标签和主体矩形组成，使用现有 `YELLOW`
- 文档由纸张轮廓和折角组成，使用现有 `DIM`
- 图标占用现有名称列左侧空间，不改变 20 px 行高和列对齐
- 选中、悬停和斑马纹背景保持现状

绘制函数只根据 `entry.is_dir` 选择图标，不参与点击或双击处理。

## 测试与验收

测试覆盖：

- `.` 开头的文件和目录均不可见，普通名称保持可见
- 可见项目数量与过滤后的列表一致
- 目录和文件选择不同的图标类型
- 双栏渲染文本中不再出现旧 Unicode 标记或隐藏条目
- 现有修改时间、列宽、重复 ID 和传输交互测试继续通过

最终使用 `native-prototype/build.sh` 完成编译、Clippy 和完整测试，并连接现有 SSH 主机截图确认目录为黄色文件夹、普通文件为灰色文档且隐藏条目不再显示。
