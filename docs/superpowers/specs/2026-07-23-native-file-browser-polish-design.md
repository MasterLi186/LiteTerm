# Native 文件管理器界面优化设计

## 目标

将 LiteTerm Native 文件管理器优化为与 `main` 分支一致的紧凑双栏界面，同时消除 egui 重复 ID 调试框，并将原始 Unix 时间戳格式化为易读时间。保留现有目录浏览、刷新、路径输入及双击传输行为。

## 问题与根因

本地和远端面板在同一 egui ID 作用域内创建相同按钮、输入框和 `ScrollArea`。egui 的调试构建检测到 Widget ID 重复，因此绘制红框及 “First/Second use” 提示。这些文字不是业务内容。

当前文件表格使用 `Grid`，名称列不会自然占满可用宽度，造成列宽失衡和大片空白。修改时间则直接调用 `mtime.to_string()`，所以显示 Unix 秒数。

## 布局与视觉

采用 egui 原生整行绘制，不引入 `egui_extras`：

- 面板背景使用 `#0d1117`，工具栏与表头使用 `#161b22`，边框使用 `#21262d`；
- 本地和远端各占一半宽度，中间保留单像素分隔线；
- 名称列自适应，大小列约 64 px，修改时间列约 94 px；
- 行高保持紧凑，使用低透明度隔行底色、青色选中态和轻微悬停态；
- 目录使用低调黄色标记，文件使用灰色标记，不再依赖 Emoji；
- 路径输入、上级目录和刷新按钮保持在各自面板顶部。

每个面板通过 `ui.push_id` 建立独立作用域，并给滚动区设置明确的 `id_salt`，从根源消除重复 ID。

## 时间格式

新增 `format_mtime(epoch)`，按本地时区输出与 `main` 相同的 `MM-DD HH:mm`，例如 `07-23 11:42`。`mtime = 0` 返回空字符串。使用 `chrono::Local` 完成跨日期和本地时区转换。

## 交互与错误状态

单击选择文件，双击目录进入，双击文件按所在侧上传或下载。加载状态、SFTP 错误、重新连接和传输进度继续显示，但颜色与间距统一到 Native 深色主题。现有 Action 和 SFTP 数据流不变。

## 验证

- 单元测试覆盖时间戳空值及 `MM-DD HH:mm` 输出结构；
- egui 测试在同一帧渲染本地和远端面板，确认无重复 ID 调试形状；
- 保留布局高度、大小格式和文件浏览状态测试；
- 使用 `native-prototype/build.sh` 完成编译、Clippy 和测试；
- 启动 Native，人工确认红框消失、两栏对齐、时间易读。
