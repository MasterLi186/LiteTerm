# Native 文件创建与删除确认设计

## 目标

完善 LiteTerm Native 双栏文件管理器的基础操作：

- 右键菜单项随鼠标悬停显示整行高亮。
- 删除文件或目录前显示确认框，避免误操作。
- 本地和远端标题栏各常驻“＋文件”“＋目录”按钮，目标位置为各自当前目录。

保持现有紧凑双栏布局、重命名弹窗、上传下载和目录刷新行为不变。

## 界面与交互

每个文件窗格的标题栏左侧保留“本地”或“远端”，右侧依次显示项目数、“＋文件”和“＋目录”。按钮使用当前 Native 深色配色和紧凑尺寸；本地按钮始终可用，远端按钮仅在 SFTP 就绪时可用。

点击创建按钮后显示居中的名称输入框。标题按操作显示“新建文件”或“新建目录”，输入框自动聚焦。名称为空、等于 `.`/`..` 或包含 `/`、`\` 路径分隔符时禁用确认；以 `.` 开头的合法名称仍允许创建。目标已存在时返回错误，绝不覆盖原文件或目录。创建成功后只刷新对应窗格。

右键菜单改用与连接菜单一致的自绘整行响应区域：普通项悬停使用灰蓝背景，删除项保持红色文字，禁用项不响应点击。

点击删除只打开确认框，不立即发送删除命令。确认框显示目标名称及完整路径；“取消”、Escape 或点击遮罩关闭弹窗，红色“删除”按钮才发送现有删除动作。目录仍沿用当前语义：本地递归删除，远端仅删除空目录。

## 状态与数据流

`FileBrowserState` 新增创建弹窗和删除确认状态。UI 将确认后的操作转换为 `Create` 或现有 `Delete` action；`main.rs` 转发给已有 SFTP worker。worker 新增创建命令和 `Create` 操作结果：

- 本地文件使用 `OpenOptions::create_new(true)` 创建空文件。
- 本地目录使用 `create_dir`。
- 远端文件使用 SFTP 的独占创建标志创建空文件。
- 远端目录使用 `mkdir(..., 0o755)`。

所有创建失败信息写入对应窗格错误区域。创建或删除成功后由现有 mutation 完成事件触发相应窗格刷新。

## 测试与验收

- 单元测试覆盖菜单 hover 绘制、删除先进入确认状态、取消不产生动作、确认生成正确删除动作。
- 单元测试覆盖创建名称校验、本地文件/目录创建、同名拒绝以及 action 路径拼接。
- SFTP 命令测试覆盖创建类型与错误归属；全部 Native 测试继续通过。
- 运行专用 `native-prototype/build.sh`，并在真实 UI 中验证本地、远端按钮、创建结果、删除确认和菜单 hover。
- 测试只使用唯一命名的临时目标，验收后清理；不修改旧 GuiShell 的 `build.sh` 与 `run.sh`。
