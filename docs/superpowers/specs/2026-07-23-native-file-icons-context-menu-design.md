# Native 文件类型图标与右键菜单设计

## 目标

在现有 Native 双栏文件管理器中增加按文件类型区分的矢量图标，并实现与 main 当前文件行右键菜单一致的完整操作。菜单必须保持在可用屏幕范围内：底部空间不足时向上展开。

## 文件类型图标

目录继续使用黄色文件夹图标。普通文件根据小写扩展名映射为：

- 代码：`rs`、`c`、`cpp`、`h`、`py`、`js`、`ts`、`go`、`java`、`sh` 等
- 文本与配置：`txt`、`md`、`log`、`json`、`toml`、`yaml`、`xml`、`ini`、`conf` 等
- 图片：`png`、`jpg`、`gif`、`webp`、`bmp`、`svg`、`ico`
- 压缩包：`zip`、`tar`、`gz`、`bz2`、`xz`、`7z`、`rar`、`zst`
- 可执行与二进制：`bin`、`elf`、`run`、`appimage`、`exe`、`so`、`dll`、`dylib`
- 其他：通用灰色文档图标

每类图标使用 egui `Painter` 绘制稳定的几何轮廓，不依赖字体。分类函数只读取文件名和 `is_dir`，不影响传输或列表数据。

## 右键菜单

右键文件行时先选中该条目，再打开约 160 px 宽的深色菜单：

- 本地文件：`上传到远程 (<远端目录名>)`、分隔线、`重命名`、`删除`
- 远端文件：`下载到本地 (<本地目录名>)`、分隔线、`重命名`、`删除`

目录的上传或下载项禁用。菜单项执行后关闭；单击菜单外或按 Esc 关闭。菜单位置由纯函数计算：优先以鼠标位置为左上角；若 `pointer_y + menu_height` 超过可用屏幕底部，则使用 `pointer_y - menu_height` 向上展开；横向和最终纵向位置均限制在屏幕范围内。

使用自定义 `egui::Area`，而不是依赖 egui 默认上下文菜单的屏幕约束，以明确保证向上展开规则。菜单状态保存在当前标签的 `FileBrowserState`，切换标签不会串用条目。

## 重命名与删除

选择“重命名”后打开居中窗口，输入框预填并全选原名称。空名称不提交；Enter 确认，Esc 或取消按钮关闭。新路径始终由当前面板路径与新名称拼接，禁止菜单直接提供任意目标路径。

行为与 main 当前实现一致：

- 本地删除文件使用 `remove_file`，删除目录使用递归 `remove_dir_all`
- 远端删除文件使用 SFTP `unlink`，删除目录使用 `rmdir`，因此非空目录返回错误
- 不额外增加删除确认框

## Worker、刷新与错误

`SftpCommand` 增加本地/远端重命名和删除命令；worker 完成后发送包含面板、操作和结果的事件。成功时 `main.rs` 请求刷新原面板，失败时在对应面板顶部显示中文错误，保留当前路径与既有列表。

上传和下载继续复用现有 action 与进度逻辑。菜单只产生结构化 action，不直接访问文件系统或 SSH 会话。

## 测试与验收

自动测试覆盖扩展名大小写和无扩展名分类、菜单条目与禁用条件、菜单向上/边界定位、空重命名校验、本地递归删除与重命名、worker 结果的刷新/错误处理，以及现有隐藏文件、时间、列宽和重复 ID 回归测试。

最终运行 `native-prototype/build.sh`，再连接现有 SSH 主机，分别在面板顶部和底部右键验证菜单位置、上传/下载、重命名、删除失败提示和自动刷新。旧 GuiShell 的 `build.sh`、`run.sh` 必须保持不变。
