# 原生 SFTP 文件管理器第一阶段设计

## 目标

为 `native-prototype/` 增加可日常使用的 SFTP 最小闭环，并保持终端传输期间可交互。行为和布局以 `main` 分支的 `FileBrowser.tsx` 与 `src-tauri/src/commands/sftp.rs` 为基线，移植为 egui + 原生 Rust 后台线程。

第一阶段包含：

- 底部可折叠的本地/远端双栏文件管理器
- 本地和远端目录浏览、刷新、返回上级、路径直接输入
- 双击本地文件上传，双击远端文件下载
- 文件名、大小、修改时间展示，目录始终排在文件之前
- 上传/下载进度、成功状态和错误提示
- 每个 SSH 标签独立保存远端路径和 SFTP 连接

删除、重命名、拖拽、目录递归传输和取消传输不在本阶段实现。

## 架构

采用“每个 SSH 标签一个独立 SFTP worker”。终端 SSH 线程和 SFTP 线程分别建立 TCP、SSH 和认证状态，避免共享 `ssh2::Session`。这与 `main` 的独立 SFTP 会话语义一致，也符合 `ssh2` 对线程所有权的限制。

新增模块：

- `sftp.rs`：认证、SFTP worker、命令与事件类型、目录读取和流式传输
- `file_browser.rs`：双栏 UI、路径与选择状态、排序和传输列表

`App` 增加以 tab ID 为键的 SFTP worker handle 和 `FileBrowserState` 映射，UI 只渲染当前标签对应的状态。`UserEvent` 增加统一的 SFTP 事件变体，用于把连接、列表和传输结果送回 winit 主线程。网络和文件 I/O 不在 UI 线程执行。

为避免 SSH 与 SFTP 认证逻辑分叉，将主机、端口、用户、认证方式、密钥路径和密码整理为可克隆的连接参数。终端连接与 SFTP worker 使用相同参数，但各自建立 Session。

## 命令、事件与状态

UI 向 worker 发送：

- `ListLocal { path }`
- `ListRemote { path }`
- `Upload { local_path, remote_path }`
- `Download { remote_path, local_path }`
- `Reconnect`
- `Shutdown`

worker 向 UI 发送：

- `Ready { home }`
- `LocalListed` / `RemoteListed`
- `TransferProgress`
- `TransferFinished`
- `Failed`

所有命令和事件都携带 tab ID；目录请求额外携带 request ID，用于丢弃后到达的旧列表。目录条目统一为 `FileEntry { name, path, is_dir, size, mtime }`。传输以 tab ID 和 transfer ID 标识，避免同名文件的事件相互覆盖。每个 worker 串行处理 SFTP 命令；大文件传输期间终端不受影响，但同一标签的下一项 SFTP 操作排队等待。进度事件最多每 100ms 上报一次，防止事件循环被高频刷新淹没。

## UI 与交互

文件管理器只在 SSH 标签显示，默认展开，位于终端下方、快捷命令栏上方。折叠条始终可见。第一阶段使用固定初始高度，不实现拖拽调高。

每个面板包含标题、路径输入框、上级目录、刷新按钮和文件表格。双击目录进入；双击本地普通文件上传到当前远端目录；双击远端普通文件下载到当前本地目录。本地默认路径为展开后的 `~/Downloads`，远端默认路径使用 SFTP `realpath(".")` 的结果。

上传和下载采用覆盖写语义，与 `main` 保持一致。完成后自动刷新目标面板。底部传输条显示方向、文件名、百分比和错误；成功项短暂保留后清除，失败项保留到下一次操作或用户切换标签。

## 生命周期与错误处理

SSH 终端认证成功后立即启动对应 SFTP worker。SFTP 建立失败不关闭终端，只在文件管理器显示错误并允许刷新触发一次重连。关闭 SSH 标签时发送 `Shutdown` 并移除 handle；若正在传输，则当前传输结束或失败后退出。

路径无权限、不存在、磁盘写入失败、远端断开和认证失败都转换为用户可读的中文错误。失败不得清空另一侧已经成功加载的目录列表。过期事件必须按 tab ID 丢弃，防止切换标签后旧结果覆盖新标签状态。

## 验证

自动测试覆盖：

- 路径拼接、父目录和 `~` 展开
- 目录优先及名称排序
- 本地临时目录列表的名称、大小和目录标记
- 传输进度节流及 transfer ID 隔离
- 标签切换时忽略过期事件

手动验证覆盖：

1. 密码、密钥和 agent 认证的 SSH 标签均能打开远端 home。
2. 本地与远端路径输入、上级目录和刷新可用。
3. 上传、下载小文件后内容一致，目标面板自动刷新。
4. 传输大文件时进度持续更新，终端输入输出保持正常。
5. 无权限目录、断网和关闭标签不会卡死或崩溃。

实现验证运行原生 crate 的格式检查和测试，并按仓库要求使用 `./build.sh` 验证现有 Tauri 应用没有回归。

## 后续阶段

在最小闭环稳定后，依次加入删除与重命名、拖拽上传、取消传输、目录递归传输和可拖拽面板高度；这些功能不提前混入第一阶段。
