# Native Bash 智能补全设计

## 背景与目标

LiteTerm Native 需要在本地 Bash 和 SSH 远端 Bash 中提供基于历史命令的智能补全。用户输入任意非空前缀后自动显示候选，使用上下方向键选择。第一次回车只把候选写入当前输入行，不执行命令；用户再次按回车后才由 Bash 执行。

本功能不修改本地或远端的 `~/.bashrc`，不影响 Fish、Zsh 等其他 shell，不复用现有快捷命令栏的 `native_cmd_history.json`。

## 方案选择

采用“会话级 Bash 集成 + 独立历史加载器 + Native 弹窗”的方案。

纯键盘事件推测无法可靠处理 Readline 光标移动、删除、粘贴和自动换行；修改 Readline 全局键位又会侵入用户配置。会话级集成通过私有 OSC 标记确定 Bash 提示符和输入起点，终端网格作为当前输入内容的可信来源，兼顾准确性和隔离性。

## 会话集成与生命周期

每个标签页拥有独立的 `CompletionState`，包含：

- 当前是否处于可编辑的 Bash 提示符；
- 提示符结束位置和当前输入前缀；
- 已加载历史、过滤后的候选和选中索引；
- 每个标签页随机生成的 OSC 校验标识。

本地标签页仅在 shell 路径的文件名为 `bash` 时启用。启动时使用临时 `--rcfile`：先加载用户原有 `~/.bashrc`，再安装只对当前进程有效的提示符钩子和专用 Readline widget。临时 RC、候选交换文件均以随机文件名安全创建，权限为 `0600`，拒绝复用符号链接或已存在路径，退出后尽力清理。

SSH 建连后以带超时的独立探测确认登录 shell。确认是 Bash 后，使用 SSH exec/wrapper 在 `umask 077` 下安全创建临时文件并启动交互 Bash；探测、临时文件准备或集成启动失败时立即回退到现有普通 `channel.shell()` 路径，不能因 SFTP 不可用阻断终端。SSH wrapper 负责退出清理。远端临时路径由 token 和 generation 确定，客户端不会接受终端输出提供的任意写入路径。

集成脚本保留用户原有 `PS1` 和字符串/数组形式的 `PROMPT_COMMAND`，LiteTerm 钩子最后运行。私有 OSC 被包在 Readline 的 non-printing prompt 标记中，不参与提示符宽度计算。钩子在每次提示符前重新安装并验证随机专用 Readline binding，避免 `.inputrc` 或用户初始化脚本改变填充语义。

私有帧精确定义为 `OSC 777;LiteTerm;<128-bit hex token>;<u64 generation>;<type>[;<payload>] BEL`。`P` 表示提示符结束；`H` 携带 Base64URL 编码的 UTF-8 `$HISTFILE`。编码工具不可用、解码失败或路径不安全时直接使用默认历史路径。集成端固定发送 BEL，识别器兼容 BEL 和 ST 终止。帧上限为 256 字节；遇到超限、非法 token、控制字符或格式错误时丢弃到终止符并复位，绝不解释为其他协议。PTY 原始字节仍完整交给唯一的持久 Alacritty Processor；额外识别器只定位私有帧结束偏移，不解析 CSI、不剥离字节，也不生成终端响应。

同一 PTY 分块内发现完整标记后，先将截至标记终止符的字节推进 Alacritty，再立即快照光标，随后继续推进剩余字节。跨分块标记使用有界状态衔接。窗口 resize/reflow、alternate screen、输入起点离开网格、起点到光标间出现硬换行或其他坐标歧义时，立即关闭补全，等待下一次有效提示符标记。提取只跨越带 soft-wrap 标志的行，并忽略宽字符占位格、保留组合字符。

任何会接受当前行的出站输入，包括 Enter、Ctrl-J、Ctrl-M、粘贴中的 CR/LF，都会先关闭提示符状态；无法证明为普通文本或已知 Readline 编辑键的控制序列也保守关闭。只有当前 generation 和 token 匹配的新提示符标记才能重新启用。因此执行 `fish` 或 `zsh` 后补全自然停用。

## 历史读取与排序

集成脚本优先报告实际 `$HISTFILE`；未设置、路径含控制字符或不符合本地/远端路径约束时，回退到 `~/.bash_history`。新建本地标签页时异步读取历史；SSH 标签页在 SFTP 就绪后，通过扩展现有工作线程读取远端历史。读取设定大小和条数上限，不阻塞 UI，也不在每次按键时访问磁盘或网络。

带时间戳的历史以 `#<epoch>` 为逻辑记录边界，跨物理行的记录整条丢弃；无时间戳时无法可靠还原多行边界，因此每个物理非空行按独立单行记录处理。所有候选过滤 CR、LF、NUL、ESC 和其他控制字符。

新标签页和 SSH 重连都会增加 generation、清空旧候选及 OSC 缓冲、重新生成 token 并加载历史；所有异步结果携带 generation，迟到的旧结果直接丢弃。当前 LiteTerm 会话中人工执行的单行命令，仅在真正向 Bash 发送执行回车前合并；第一次候选填充不计入历史。

候选采用稳定的混合排序：

1. 前缀匹配优先；
2. 其后为包含匹配；
3. 每组按最近使用顺序排列；
4. 完全相同的命令只保留最新一条；
5. 排除与当前输入完全相同的候选。

历史文件按“末行最新”解释，会话新执行项优先于文件项。匹配采用大小写敏感的 Unicode 字符串比较，不做模糊匹配；同组并列时保持反向时间顺序。默认最多展示 8 条。

## 输入处理与弹窗

处于有效 Bash 提示符且输入非空时，Native 从 OSC 记录的输入起点读取到当前终端光标，支持 Readline 编辑和终端自动换行。输入变化后重新匹配候选。

弹窗锚定终端光标，优先显示在下方；空间不足时向上展开，并始终裁剪在终端可视区域内。样式沿用 Native 深色紧凑布局，当前候选整行高亮。

- `↑` / `↓`：仅在弹窗可见时切换候选，否则原样发送给 Bash；
- `Esc`：关闭弹窗；
- `Enter`：有选中项时先把候选写入该标签页的 `0600` 临时候选文件；写入成功后只发送随机专用 widget 序列，由 widget 直接设置 `READLINE_LINE` 和 `READLINE_POINT`，随后关闭弹窗；
- 再次按 `Enter`：按现有终端逻辑发送 `\r` 并执行；
- 其他输入、退格、粘贴和光标移动：交给 Bash，终端回显后刷新匹配。

本地文件写入失败或远端 SFTP 写入失败时，不发送 widget 序列、不改变 Bash 输入行，并保留可重试状态。填充流程携带 tab ID 和 generation，切换标签页、关闭连接或重连后到达的完成事件不得写入任何终端。

专用 widget 使用 token 派生且不与标准终端键冲突的随机序列，并通过 `builtin bind -x` 分别绑定到 Emacs、Vi insertion 和 Vi command keymap。执行体只读取受限候选文件并赋值给 `READLINE_LINE/READLINE_POINT`，不调用 `eval`、不发送按键宏、不执行文件内容。候选文件内容不含任何控制字符，widget 序列本身也不映射到 `accept-line`；每次提示符显示前都会重装绑定。因此第一次回车不依赖 End、Ctrl-U 等可被用户重绑定的按键，并保证不触发执行。

## 错误处理与安全边界

历史文件不存在、无权限、SFTP 未就绪、shell 探测异常或远端不是 Bash 时，仅禁用该标签页的智能补全，不影响终端使用。OSC 标记、异步文件事件和 widget 请求必须同时匹配标签页、generation 与随机 token，避免普通终端输出或旧连接误触发状态。

## 测试与验收

单元测试覆盖历史解析、去重、混合排序、候选上限、OSC 分片/偏移/超限/伪造标记、generation 隔离、soft-wrap 输入区提取、歧义失效、弹窗上下翻转，以及填充请求不包含执行字符。集成测试覆盖本地 Bash、SSH Bash、重连、切换 Fish/Zsh、历史文件缺失、SFTP 失败和超长命令。

手工验收重点：

1. 输入任意非空前缀自动出现候选；
2. 上下键选择，第一次回车只填充，第二次回车才执行；
3. Readline 左右移动、退格、粘贴和长行换行后候选仍正确；
4. 新执行命令无需重载文件即可进入候选；
5. Emacs/Vi 模式以及把 End、Ctrl-U 重绑定为 `accept-line` 时，第一次回车仍只填充；
6. Fish/Zsh、普通终端输出及远端网络异常不会误触发或阻塞终端。
