# Native 侧栏与命令历史界面设计

## 背景

Native 在最大化窗口后仍使用大量 9–11px 侧栏文字，信息密度过高且难以辨认。监控卡片还存在内容宽度收缩、进程行背景未铺满、CPU 型号挤在单行、网络面积填充过重等问题。命令历史窗口固定锚在终端左下角，与触发按钮和 GuiShell 布局均不一致。

## 目标

- 放大整个左侧栏，不改变文件管理器、终端和通用弹窗字号。
- 保持约 220px 侧栏宽度，使用折行和弹性布局消化更大的文字。
- 让卡片和行背景占满侧栏内容宽度。
- 将网络历史改为无面积填充的实时折线图。
- 让命令历史基于历史图标定位，并对齐 GuiShell 的内容和操作布局。

## 侧栏排版

侧栏使用集中定义的字号和尺寸：

- 正文、连接名称、进程和磁盘内容：12px。
- 分组、辅助信息和表头：11px。
- 重要数值：13px。
- 卡片标题：12px。
- 连接行和监控行同步增高，避免放大后裁切。

不修改全局 egui `TextStyle`，防止影响文件管理器、菜单和配置弹窗。

## 监控卡片

运行时间卡强制占满可用宽度，运行时间与系统负载各占一半。资源卡把 CPU 标题和百分比放在首行，CPU 型号放在下一行并允许自然折行；内存和交换保持紧凑单行。

进程列表为每项预先分配完整行矩形，交替色、悬停色和高亮色都绘制到整行，而不是包裹内容。内存、CPU 和命令列保持固定对齐，过长命令截断显示。

网络卡保留上传绿色、下载蓝色两条共享时间轴的折线，使用当前历史数据和动态纵轴；移除闭合多边形与半透明面积填充。

## 命令历史

命令栏保存历史按钮的实际屏幕矩形。历史窗口以按钮右上方为基准向上弹出，右边缘优先与按钮对齐，并根据屏幕边缘自动夹紧。

窗口内容对齐 GuiShell：

- 顶部显示“命令历史（数量）”和清空操作。
- 每行显示截断的等宽命令文本。
- 提供填入输入框、立即执行、复制和收藏操作。
- 点击外部关闭；窗口高度受可用空间和历史数量限制。

收藏弹窗保持现有行为，本次只调整命令历史。

## 测试与验收

为字号配置、全宽行矩形、CPU 双行布局、无填充折线数据、弹窗锚点与屏幕夹紧增加可测试的纯布局函数或 egui 无头测试。

完成后运行 `cargo fmt --check` 和 `native-prototype/build.sh`。在 1280×800 最大化窗口及较窄窗口中截图验证：侧栏文字清晰、卡片全宽、CPU 正确折行、进程背景铺满、网络仅有折线、历史窗口紧邻按钮且不越界。
