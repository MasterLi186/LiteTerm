# Native 终端单击选区设计

## 背景

Native 终端当前在鼠标左键按下时，立即把当前字符格同时设为选区起点和终点。渲染器会反色这个单格选区，因此普通单击也会留下一个跟随点击位置的白色亮块；释放时还可能把单个字符复制到剪贴板。

## 目标

- 普通单击仅聚焦终端，不显示选区、不触发复制。
- 在按住左键并跨越字符格后，才创建并显示拖拽选区。
- 保留双击选词、三击选行以及选中后自动复制。
- 保留终端鼠标报告模式和 `Shift` 强制本地选择行为。

## 设计

在 `App` 中增加独立的拖拽起点状态。左键首次按下时清除旧选区、记录当前字符格，但不设置 `selection_start` 或 `selection_end`。

鼠标按住移动时：

- 若仍位于起始字符格，不创建选区。
- 若进入其他字符格，使用拖拽起点和当前字符格建立选区。
- 后续移动只更新选区终点。

左键释放时，仅当实际选区存在时才复制文本，随后清除拖拽起点。双击和三击继续直接调用现有的选词、选行逻辑，不依赖拖拽起点，因此单字符单词仍能正常高亮。

渲染器的选区判断保持不变，避免将“单格拖拽选择”和“单字符双击选择”错误地一并隐藏。

## 测试与验收

抽取纯状态转换辅助逻辑，并按 TDD 覆盖：

- 单击按下只记录起点，不创建选区。
- 同一字符格内移动不创建选区。
- 跨字符格拖拽创建选区并持续更新终点。
- 原地释放不复制；真实拖拽释放允许复制。
- 双击选词、三击选行路径保持不变。

完整运行 `cargo fmt --check`、`native-prototype/build.sh`，并在 X11 下实测普通单击无亮块、拖拽与多击选择正常。
